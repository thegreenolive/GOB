# 02.5 Problem, Solution, Implementation

Solving a problem effectively starts with ensuring you are solving the right problem. Often, clients ask for a solution that doesn't address the underlying cause of their issue. In Chapter 00 of this guide, a general approach for identifying and analyzing problems was presented. Now, when translating a problem description to a workable model, a good approach is to use a three-part framework.

* **Problem Domain Issues**: Determining the kind of data involved, its source, and any constraints or restrictions on the problem's size.
* **Solution Domain Issues**: Identifying the tools and techniques available to generate the solution and how that solution will be communicated to the user.
* **Implementation Issues**: Assessing the user's skill level and the specific technical requirements, such as the operating system or software required to run the solution.

Some situations are so complex that they cannot be analyzed/solved using a single model. For example, the interactions among the components of a vehicle need to be modeled for different “modules” (e.g., ignition, cooling, etc.), as well as how those modules cooperate.  This is known as modularity. **Modularity** involves decomposing a large, complex problem into smaller, self-contained parts or "modules". In programming, these modules are called by other modules to perform specific functions.

Inside modules, there could be nested modules organized in a specific hierarchy. **Hierarchy** establishes the "flow" of these modules. Solving high-level problems requires solving lower-level problems in a specific sequence. For example, “calculating a student’s GPA” is a high-level task that requires the lower-level tasks of "Collect Data," "Calculate GPA," and "Report GPA".
