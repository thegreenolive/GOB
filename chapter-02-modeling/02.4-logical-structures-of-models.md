# 02.4 Logical Structures of Models

In most cases, a model is given a certain order or structure. The way models are organized is not arbitrary. Models are structured based on how tasks or data relate to one another. The following list describes the most common ways to organize a model. The list is not comprehensive, as domain-specific models have unique requirements.

* **Linear**: This structure enforces a strict sequence where you proceed from one task to the next without ever going back. An example is building a house: you must pour the foundation before framing the walls.
* **Hierarchical**: This structure models "belonging to" relationships, where a "child" activity belongs to only one "parent". This is used for decomposing complex tasks into smaller, manageable "chunks" of work.
* **Network**: A generalization of the hierarchical structure that allows a "child" to have more than one parent. These are used for flowcharts, project management (CPM), and optimization models.
* **Matrix/Table**: These use rows and columns, with formulas defining relationships between data cells, as commonly seen in spreadsheets.
* **Object-Oriented Programming (OOP)**: This paradigm allows for programmer-defined data types beyond simple numbers. Objects are defined by their attributes (data) and methods (behaviors). This type of structure will be discussed in future sections of the GB.
