# 02.4 Logical Structures of Models

In most cases, a model is given a certain order or structure. The way models are organized is not arbitrary. Models are structured based on how tasks or data relate to one another. A **linear structure** enforces a strict sequence where you proceed from one task to the next without ever going back. An example is the numbered sequence in most recipes: you must whip the butter before baking the cookies. Now, there are some models in which a task can depend on several other tasks or have “multiple parents.” In those cases, a **network structure** is more appropriate. These are used for flowcharts, project management (CPM), and optimization models.&#x20;

Another type of model structure is used to describe those cases where “parts” of a model “belong to” a “parent” model. This **hierarchical structure** model is used for decomposing complex tasks into smaller, manageable "chunks" of work.  Some situations are so complex that they cannot be analyzed/solved using a single model. For example, the interactions among the components of a vehicle need to be modeled for different “modules” (e.g., ignition, cooling, etc.), as well as how those modules cooperate.  This is known as Modularity. **Modularity** involves decomposing a large, complex problem into smaller, self-contained parts or "modules". In programming, these modules are called by other modules to perform specific functions.

Using the example of the _pi_ company, Figure 02.5 shows an example of a linear model and a network model of how to craft a pie. Be aware that the “Preheat oven” task is assumed to be included in the “Bake pie” task in the linear model. In the network model, the “Preheat oven” task is a single one. Be aware that the network model may be considered more efficient because, technically speaking, two tasks can be performed concurrently.

Figure 02.6 illustrates a hierarchical model for baking a pie. Each task in the diagram is broken down into subtasks that are independent of one another. How far to break down a hierarchical model depends on the user's convenience.

Certain business applications use a spreadsheet to represent relationships between data cells. These Matrix or table models are very useful for representing situations involving simple mathematical operations on quantities. In this guide, spreadsheets will be used to represent simple programs and their execution on a computer.

A special model structure is the one used in Object-Oriented Programming (OOP). This structure allows for programmer-defined data types beyond simple numbers. Objects are defined by their attributes (data) and methods (behaviors). This type of structure will be discussed in future sections of the GB.
