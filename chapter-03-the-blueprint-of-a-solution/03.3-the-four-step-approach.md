# 03.3 The Four-Step Approach

After having a good understanding of the three domains of the problem, the framework calls for a specific four-step methodology:

1. State the problem.
2. Design the I/O.
3. Design the processing.
4. Implement the solution.

The first step, problem formulation, is often the most essential and difficult, as the original statement provided by a user usually omits details assumed to be known. Since the problem domain may differ from the programmer's domain, the programmer may fail to ask key questions. A programmer from Spain asking questions about a solution that calculates distances using GPS technology in the USA could miss asking questions about the units to use (metric vs imperial). A good problem statement must be shaped by the various domain issues and provide a clear mandate for the computer program.

The second step, designing the I/O, involves creating a simple list or graphical model of the required inputs and outputs. This part focuses on specifying how the data will be entered and the results (outputs) provided. Inputs are usually provided by the user or retrieved from storage, while the outputs (solutions) are presented to the users or stored. At this stage, the programmer may return to ask questions of the problem stakeholders or make decisions based on their understanding of the problem.

The logic for transforming the input is implemented in the third step, processing design. All the steps required to produce the output can be outlined using tools such as flow diagrams or pseudocode to outline the data processing. This design is separated from the actual programming, which is carried out in the fourth step. The fourth step involves the actual construction of the program, followed by testing and installation.

It is important to note that this approach is a simplification intended for simple problems. As problem complexity increases, a formal, professional methodology (e.g., Agile) is required. Nevertheless, the four steps shown in this section are still the foundation of coding practices.
