# 03.4 Walkthroughs

In this section, students will use walk-throughs to review the steps explained in the previous section. A walk-through is a systematic process used to verify the logic of a solution before or during its implementation in a computer environment. Walkthroughs simulate some of the resources available to programmers when actually programming a solution, but seek to expand understanding of how to plan the coding.

This process begins with a human level walk-through (humanual), where a person uses pencil and paper (the example uses a spreadsheet-like tool) to solve the problem manually. By first identifying the input and expected output, the designer ensures the logic is general enough to handle various scenarios without relying on anomalies or shortcuts.

The next level is the program level walk-through. In this phase, in addition to the inputs and outputs, all “memory slots” used to assist computations are specified. The complexity of a walk-through increases from the human level to the program level. Finally, a deeper walkthrough covering the hardware components and how they perform fundamental CPU-level operations is the next level, but this type will not be covered in this guide.

#### Program level walk-through

The Program level Walk-through includes the variables that are "hidden" from the user. In Problem 1, the solution needs to do two things: (1) keep track of the number of inputs that the user has provided and (2) keep the sum of the values that have been input so far. According to this logic, there is a need for two new variables: <mark style="color:red;">count</mark> and <mark style="color:red;">sum</mark>. These two new variables are _Working Storage_, a set of variables that aid the resolution of the problem but are not shown to the user. The set of variables that comprises the working storage needs to be created and initialized every time the program runs. In most programs, the working storage is hidden from the final user.&#x20;

Before going step by step through the Program-level Walk-through, some notation used in the instructions needs clarification.

* Actual values are included in the instructions by using the symbol "**=>**" to indicate "**evaluates to**".
*   Consider increasing the value "<mark style="color:red;">count</mark>" variable by 1:

    * This operation is used to track the number of inputs the user has entered
    * The equation form indicates how that happens:
      * "<mark style="color:red;">count</mark> **=** <mark style="color:red;">count</mark> **+1**" or in some programming languages "<mark style="color:red;">count</mark>**++**"
    * Given the _**value**_ of "<mark style="color:red;">count</mark>", "<mark style="color:red;">count</mark>**++**" is evaluated using the "**=>**" symbol
    * &#x20;For example, if <mark style="color:red;">count</mark> **= 2**, then the instructions would look like this:

    &#x20;                                 <mark style="color:red;">count</mark> **=** <mark style="color:red;">count</mark> **+ 1**   **⇒      = 2 + 1 = 3**

There are some points to consider. Even though there are 10 steps in the whole program, it is possible to identify three "general" steps in the program:

1. **Initialize the variables**. Done in _Step 1_.
2. **Get input and check whether the next one is needed**. Done twice, in _Steps 2 to 5_ and _Steps 6 to 9._
3. **Report output**. Done in _Step 10._

The General Step 2 can be repeated as many times as there are numbers to sum. This way of reusing a set of instructions in code is a common practice and a staple of programming.
